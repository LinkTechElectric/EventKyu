# 漫展切 cue 软件 — 整体技术架构设计

> 版本：v2.0（2026-10-23，第五、六轮调研后修订）
> 前置文档：《漫展切cue软件可行性报告.md》（十四章调研结论）
> v2.0 变更：① macOS 端改为 Swift & Metal 原生封装（Windows 端保持 Tauri+Rust）；② 音频引擎升级为「分设备电平/电平表 + 实时降噪 + 声卡输入路由至虚拟输出」，并因此提前锁定 L3 全量自解码音频管线。

## 1. 产品组成与进程架构

```
┌──────────────────────────────────────────────────────────────────┐
│ 主软件 ConCue（舞台切 cue 工作站）                                   │
│                                                                    │
│  ┌─ macOS 端（原生）─────────────┐  ┌─ Windows 端 ────────────────┐ │
│  │ AppKit 窗口管理 + SwiftUI 界面 │  │ Tauri 2 + Rust               │ │
│  │ Metal 渲染 / libmpv GL 嵌入    │  │ WebView UI + Rust 渲染桥     │ │
│  │ Core Audio 音频引擎            │  │ WASAPI 音频引擎              │ │
│  └──────────┬───────────────────┘  └──────────┬─────────────────┘ │
│             │        UniFFI / FFI 共享核心      │                   │
│  ┌──────────▼─────────────────────────────────▼─────────────────┐ │
│  │ Rust 共享核心（staticlib / crates）                             │ │
│  │  cue-core 状态机 · download-core（yt-dlp+插件）·                │ │
│  │  runtime-manager（依赖体检/下载器）· plugin 协议 · AI 编排        │ │
│  └───────────────────────────────────────────────────────────────┘ │
│  外部进程：yt-dlp / ffmpeg / Deno / soffice（sidecar）               │
└──────────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────────┐
│ 副软件 SignalFit（信号适配器 + 媒体工具箱，独立二进制）                  │
│  实时链路：Syphon/NDI/DeckLink/UVC 输入 → libplacebo/wgpu 缩放        │
│           → 1080P Syphon/Spout/NDI 输出                              │
│  离线工具箱：AI 编排（BYOK）/ 手动预设 → 白名单执行 ffmpeg / 超分 CLI    │
└──────────────────────────────────────────────────────────────────┘
```

**分工原则**：平台强耦合层（窗口、渲染、音频 HAL、帧共享）各端原生实现；业务逻辑（cue 状态机、下载、插件、依赖管理、AI 编排）收进 Rust 共享核心，macOS 端经 **UniFFI** 生成 Swift 绑定调用（Mozilla 生产级方案，Firefox 在用），保证双端逻辑零漂移。

## 2. 技术栈决策（v2.0 最终选型）

| 层 | macOS 端 | Windows 端 | 共享 |
|---|---|---|---|
| 应用壳 | **Swift：AppKit（多窗口/NSScreen 全屏输出）+ SwiftUI（控制界面）** | Tauri 2 + Rust + WebView2 | — |
| 视频内核 | **libmpv（IINA 模式：GL render API 嵌入自建 FBO）** | 同左 | cue-core 调度 |
| 渲染输出 | **Metal**（Syphon Metal / NDI 发送 / 舞台窗） | D3D11 桥（WGL_NV_DX_interop 或自嵌 libplacebo） | frame-share trait |
| 缩放/色彩 | libplacebo（随 libmpv）；副软件直接嵌入 wgpu/Vulkan-MoltenVK | 同左 | — |
| 音频引擎 | **Core Audio（AUHAL/AUGraph 逐输出链）+ RNNoise** | **WASAPI + miniaudio 混音 + RNNoise** | 音频引擎 trait / DSP |
| 帧共享 | **Syphon（Metal server）+ NDI（libndi.dylib，Swift 直调）** | **Spout（rust-spout2/SpoutSDK）+ NDI（grafton-ndi）** | — |
| 业务核心 | ← **Rust staticlib → XCFramework → UniFFI Swift 绑定** → | Tauri 原生 | cue-core / download-core / runtime-manager / ai-orchestrator |
| 下载层 | yt-dlp（standalone sidecar）默认 + 插件接管 | 同左 | download-core |
| PPT | LibreOffice headless 转换（按需下载）+ 系统 Office AppleScript 增强 | 同左（COM 自动化） | — |
| AI 编排 | BYOK LLM → argv 白名单执行（副软件） | 同左 | ai-orchestrator |
| 开源协议 | **GPL-3.0** | 同左 | — |

### 2.1 关键否决与理由

- **AVFoundation 替代 libmpv：否决。** 不支持 MKV/FLV/WMV 容器与 RTSP/RTMP，无第三方编解码扩展——漫展素材来源杂，风险不可控。
- **mpv gpu-next/MoltenVK 嵌入：否决。** macOS 上已知闪烁、高刷屏 vsync 抖动、色彩空间崩溃等问题；嵌入场景走 libmpv OpenGL FBO（IINA 验证多年的成熟路线）。
- **AVAudioEngine 做多输出：否决。** input/output 共享隐藏聚合设备、只能绑单一设备、默认输出切换即失效。正解：**每条输出链一个 AUHAL/AUGraph 实例，各自绑定设备**。
- **FFmpeg 自解码 + 自研 Metal 视频渲染：暂缓。** 帧级掌控最好（零拷贝同喂 Syphon/NDI/预览），但要自实现 seek/音画同步；首版 libmpv，NDI 若成核心卖点再演进。
- **Windows arm64：不做**（NDI 官方无库，硬阻塞）。

## 3. 渲染与帧共享管线（Syphon / NDI / Spout）

### 3.1 macOS 路径（Swift & Metal）

```
libmpv → mpv_render_context（OPENGL）→ 自建 GL FBO（CAOpenGLLayer / 离屏）
  → GL 纹理经 IOSurface 互转 → MTLTexture
  ├─→ Syphon：SyphonMetalServer.publishFrameTexture（一等 Metal 支持，
  │            与 GL client 互通，~1ms 零拷贝）
  ├─→ NDI：纹理回读 CPU → NDIlib_send_send_video_async_v2
  │        （Swift 经 bridging header / dlopen 直调 libndi.dylib；
  │         先例：alessionossa/swift-ndi、Shigawire/ndi-webcam）
  └─→ 舞台输出窗：NSScreen 指定显示器全屏（AppKit）
```

先例背书：**IINA**（Swift + libmpv，GPL-3.0）为嵌入范式；**Syphoner v2.0**（SwiftUI + Metal + Syphon 输出管线）为 Swift 侧帧共享范式。

### 3.2 Windows 路径（Tauri + Rust，x64）

```
libmpv → GL FBO → WGL_NV_DX_interop → D3D11 shared texture
  （或自嵌 libplacebo D3D11 后端直接取共享纹理）
  ├─→ Spout Sender（rust-spout2 DirectXSender，GPU copy 无回读）
  ├─→ NDI（grafton-ndi；D3D11→staging→CPU 异步回读，双/三缓冲）
  └─→ 第二屏全屏窗口
```

### 3.3 性能与合规（双平台通用）

- NDI 发送必过 CPU 回读：1080p60 BGRA ≈ 500MB/s，4K60 ≈ 2GB/s，异步回读 + 多缓冲摊平。
- HDR 内容渲染端 tone-map 到 SDR 再发出；BT.601/709、limited/full range 统一由 libplacebo 色彩管理处理。
- NDI 合规：动态加载用户自装 Runtime（DistroAV 模式）；署名「NDI® is a registered trademark of Vizrt NDI AB」+ ndi.video 链接；产品名不含「NDI」；首次启用展示 EULA。

## 4. 音频信号管理（v2.0 重写）

### 4.1 新需求 → 架构后果

「分设备电平 + 降噪 + 输入路由虚拟输出」三项功能等于宣告**必须走 L3 全量自解码管线**——libmpv 只能输出到单一设备、不向宿主暴露 PCM（无音频回调），拿不到帧就做不了 per-device 增益/电平表/多设备同时输出。**mpv 降级为纯视频轨（静音），全部音频由自研引擎接管**（FFmpeg 解码 → 引擎总线）。

### 4.2 引擎结构（双端同一组抽象 trait）

```
输入侧：
  麦克风/声卡输入（AUHAL 读 / WASAPI capture）
  媒体解码（FFmpeg：音乐/视频音轨/PPT 伴音）
    → 每通道条：增益 → 降噪（NS 插件槽）→ 电平表 → 声像
总线侧：
  混音矩阵（QLab patch 模型：cue → crosspoint → patch）
    → 每条输出链独立绑定一个设备：
        · 物理声卡（主 PA / 返听）
        · 虚拟输出（BlackHole / VB-Cable，供 OBS/直播/其他 app 读取）
        · 系统输出
    → 每链：per-device 增益 + 电平表 → 限幅器（永远最后）→ 设备
透传侧（input → virtual output 路由）：
  声卡输入 → 降噪（可选）→ 环形缓冲 → 写虚拟输出
  （与混音总线共用实时线程模型，可旁路独立运行做纯监听）
```

**统一 trait（双端实现）**：`device_enum` / `per-device gain & meter` / `NS 插件槽` / `input→output 透传`。macOS 用 Core Audio AUHAL/AUGraph 实现，Windows 用 WASAPI（windows-rs / cpal 封装）实现。

### 4.3 降噪选型

| 方案 | 许可 | 延迟 | 开销 | 定位 |
|---|---|---|---|---|
| **RNNoise** | BSD-3 | +10ms（10ms 帧） | 单核 1–3%，模型 85KB，纯 C 可 vendor | **默认**（嵌入成本最低） |
| DeepFilterNet3 | MIT/Apache-2.0 | +40ms（LL 版 ~10ms） | 单线程 RTF≈0.19 | 质量上限档（Rust 原生，对 Windows/Rust 侧友好；已停更需自维护） |
| WebRTC APM | BSD | 10ms 帧 | 中等 | 需要 AEC/AGC 全家桶时 |
| macOS VoiceProcessingIO | 系统 | — | — | 系统级 AGC/AEC/NS，可作为 macOS 端的零成本选项 |

引擎内做 NS 插件槽，RNNoise 内置默认，DeepFilterNet / VoiceProcessingIO 作为可切换后端。

### 4.4 虚拟输出与路由的落地形态

**务实路线：应用内透传引擎 + 复用第三方已签名虚拟驱动**（不做 Loopback 式自研驱动——macOS 驱动公证、Windows 驱动签名成本太高）：

- macOS：**BlackHole**（HAL 插件，Apple Silicon 原生，零附加延迟；GPL-3.0——本项目同许可可分发，但仍建议引导用户装官方签名 pkg，规避驱动分发责任）；
- Windows：**VB-Cable**（免费 donationware；应用采集麦克风 → 降噪 → 渲染到 CABLE Input，其他应用选 CABLE Output 当麦克风）。先例：noisegate（Rust，WASAPI + RNNoise + VB-Cable，与本需求同构）。

### 4.5 现场稳定性要点

- 聚合/多输出设备：除时钟源外所有设备必须开 **Drift Correction**，否则几分钟后爆音；macOS 不支持调 Multi-Output Device 总音量，只能逐设备调（正好由我们的 per-device 电平接管）。
- 唇同步：视频画面走 mpv，音频走自研引擎——**必须以 mpv 画面时钟为基准对齐**（ITU-R BT.1359：音频超前 ≤45ms 可察觉；返听理想 <4ms）。
- 音频引擎做成独立模块 + 实时线程（MMCSS / Core Audio 实时优先级），崩溃隔离考虑后续拆守护进程。

## 5. 下载层（默认 yt-dlp + 插件接管）

（维持 v1.0 设计，见可行性报告第十四章）

链接 → 平台识别 → 插件已安装？是→插件方法 / 否→yt-dlp 默认；插件失效自动回退 yt-dlp。
要点：standalone 二进制内置；复用官方 `yt_dlp_plugins` 机制（插件优先于内置 extractor）；插件签名校验 + 用户确认（官方不审查插件代码）；启动自动更新 + 失败回退内置版；YouTube 需 Deno ≥2.0 配合（内置）；法律声明「仅下载用户有权下载的内容」；小红书/网易云插件不进主仓库。

## 7. 内置运行时下载器设计（Runtime Manager）

（维持 v1.0 设计）

manifest.json（版本钉死 + 各平台 URL + SHA-256）→ 官方源直链（GitHub releases、ndi.link）→ 镜像回退（npmmirror/ghproxy 模式）→ 断点续传 → SHA-256 校验不通过不落盘 → 安装到应用私有目录 → 专有组件（NDI）先展示 EULA。

触发分级：演出必需组件全打进安装包；NDI/LibreOffice 首启用时下载；BlackHole/VB-Cable/Office 引导手动装；yt-dlp 常驻自动更新。**「演出模式自检」**：一键检查所有已启用功能的依赖就绪状态（绿/黄/红）。

## 8. 双平台构建与分发矩阵

### 8.1 构建目标

| 平台 | 构成 | 打包 |
|---|---|---|
| macOS | Xcode 工程：Swift app + Rust 核心（`cargo crate-type=staticlib` → lipo universal `.a` → `xcodebuild -create-xcframework` → UniFFI `uniffi-bindgen generate --library` 生成 Swift 绑定） | universal .app/.dmg（arm64 + x86_64） |
| Windows | Tauri 2，`x86_64-pc-windows-msvc` | NSIS 安装器 |

### 8.2 签名与公证

- macOS：Apple Developer $99/年（Developer ID + notarytool；sidecar dylib 全部同证书签名——media-kit 的 libmpv 构建已签名，自编译需重签）。
- Windows：**SignPath Foundation 免费 OSS 证书**（OV 级、HSM 托管、GitHub Actions 集成、README 署名）。

### 8.3 CI/CD（GitHub Actions）

macOS job：cargo staticlib（双架构）→ XCFramework → UniFFI 绑定 → Xcode 构建 → 公证。
Windows job：cargo + Tauri 构建 → SignPath 签名。
统一：manifest.json 组件版本与 CI 钉版同步；release 附 SHA-256 清单；应用内更新器检测。

## 9. 仓库结构（v2.0）

```
concue/
├─ apps/
│  ├─ concue-mac/        # macOS 原生 app（Xcode 工程：AppKit+SwiftUI+Metal）
│  ├─ concue-win/        # Windows app（Tauri 2）
│  └─ signalfit/         # 副软件（Rust + wgpu，双平台）
├─ core/                 # Rust 共享核心
│  ├─ cue-core/          # cue 状态机/时间线（UniFFI 导出）
│  ├─ download-core/     # yt-dlp + 插件协议 + 回退
│  ├─ runtime-manager/   # 依赖体检/内置下载器/自更新
│  ├─ ai-orchestrator/   # BYOK LLM → argv 白名单（副软件用）
│  └─ concue-uniffi/     # UniFFI 接口定义（.udl / proc-macro）
├─ platform/
│  ├─ mac/               # Swift 侧：渲染（Metal/Syphon/NDI）、音频引擎（AUHAL 链）、桥接
│  └─ win/               # Rust 侧：frame-share（Spout/NDI）、WASAPI 音频引擎
├─ dsp/                  # RNNoise vendor、DeepFilterNet 可选、电平表/限幅（尽量 Rust 共用）
├─ plugins/              # 官方插件示例
├─ manifest/             # manifest.json + SHA-256 清单
└─ docs/
```

音频 DSP（降噪/电平/限幅/环形缓冲）尽量放共享 Rust 层（RNNoise 有纯 Rust 移植 nnnoiseless，DeepFilterNet 本就 Rust），双端 HAL 只是薄壳。

## 11. 架构决策记录（ADR）

| # | 决策 | 结论 | 备选/回退 |
